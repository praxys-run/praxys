Owner: Architecture. Inactive capability must merge to trusted main first;
activation is a separate PR. The implementation-only versioned binding identifies
repository/PR, immutable base and reviewed head, canonical binary diff digest,
final active contract digest, independent validation producer, workflow revision,
run/attempt, artifact identity and content digest. The complete envelope digest
is visible in the exact authenticated human statement.

Trusted code projects requested accepted/active lifecycle without mutating the
proposal. Initial activation reconstructs the final tree from the exact reviewed
preapproval commit, replaying only deterministic approved science lifecycle and
ledger generation. Every unexplained change fails, including generated paths.
The validation covers the projected active contract, not just inactive code.
Existing v1 evidence/decision semantics, accepted-record history and successor
rules remain. No service or datastore is introduced.

Validation uses a trusted-main workflow with an isolated candidate runner,
read-only token, no persisted credentials or production secrets. A separate
trusted collector recomputes source/diff/projected contract and reads successful
required job metadata; candidate outputs cannot assert their own success. Bind
actual workflow revision separately from tested candidate revision. Missing,
failed, skipped, stale, wrong-producer or rerun evidence fails closed. Fresh
Quality independently reviews the frozen source and exact validation run.

Final correction: explicitly enumerated trusted governed files protect subsequent
maintenance; no broad application-directory freeze or inferred prose globs.
Coverage includes numerical/parser/runtime code, shared authorization and
lifecycle dependencies, clients/claims, science approval/validation machinery,
workflows and dependency locks. Initial activation still compares the whole tree.
Later unrelated files may change; governed changes require separately reviewed
renewal, which this capability does not implement. Verified migration-compatible
inactive PR839 rollback is the recovery boundary. Earlier possible revocation or
successor automation is deferred and is not an implementation mandate.
