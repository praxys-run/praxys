# Useful product, reliable engineering

`AGENTS.md` is the session policy. One session understands the user problem,
implements a simple solution and verifies it. For product changes, read
`PRODUCT.md`; for UI, use `ui-quality` and exercise the rendered primary journey.
For engineering, verify correctness, security, performance and maintainability.
These are two acceptance criteria applied throughout one working loop.

| Profile | Purpose |
|---|---|
| Praxys Orchestrator | Execute in the current session; no extra executor launch. |
| Quality | One fresh read-only review for material risk, covering all relevant concerns. |
| Operations | Optional isolated tools for explicitly authorized operations. |

Routine changes use focused checks. Required CI supplies full regression checks.
The optional `scripts/agent_preflight.py` batches local checks; neither its command
nor a SHA paragraph is a readiness credential. Recheck affected behavior after a
fix and stop when acceptance is met. A final response or PR records the outcome,
actual validation and remaining limitations. Create a durable decision document
only when it explains a lasting choice or an existing domain schema requires it.

Task routing/config schemas, classification digests, invocation ledgers,
per-task decision cards and specialist handovers are removed. Native runtime
owns planning, context and lifecycle. Claude uses the same Quality review;
science, metric-delivery and API checks are checklists within that review.

Scientific acceptance/activation, consent, branch protection and deployment
permissions remain real boundaries. Existing science or external-tool contracts
may bind approvals to immutable subjects; ordinary task execution never asks
for digest or version confirmation. Root MCP scope and credential filters are
unchanged. Static adapter checks verify tooling and sandbox boundaries, not
model quality or speed.

Use observed user outcomes, escaped regressions and actual task time to assess
this policy. Fix the relevant check when a failure escapes; do not add another
process layer merely to count tasks. No improvement in latency or defect rate
is claimed without measurement. Revert the change to roll back; historical
records and private ledgers are retained as history and are not task entry points.
