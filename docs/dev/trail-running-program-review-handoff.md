Science 本轮为只读增量核验。表中“共同依赖／范围扩展”表示科学依赖层次，
不是交付项 P1–P8 的编号，也不代替 Product 的交付优先级。

| 50 公里 | 多维赛事需求证据可复用；现有 Trail 距离字段上限 49,999 米 | 新距离／时长范围及长时、补给、环境、疲劳政策；50 公里不是生理断崖，但超出现有契约；本轮未完成专项研究 | 范围扩展 |
| 持续进阶 | accepted 自适应 SDR 支持观察、反馈和复核语义，未接受具体 progression/dose；v3 首块不自动加量 | 进阶变量、触发、冲突信号、停训后恢复、跨模块总量及停止；固定百分比或 ACWR 区间不是安全证明 | 范围扩展 |
| 跑走／徒步、补给、减量 | 既有证据支持按预计时长和耐受考虑补给；广义耐力减量有方向支持；v2/v3 具体剂量未接受 | 转换规则、补给量及练习、减量起点和各类负荷分别立政策；不能直接搬入其他人群比例、频率或百分比 | 范围扩展 |

一个交付项可以产生多个独立 SDR 决定，不必将不同人群和剂量合并为一次批准。
未来 Evidence Review 分开核验基础能力、实验室下降转移和真实越野结果；新 SDR 给出
适用范围、输入、候选值分类、组合、未知处理与可证伪条件。无唯一研究剂量时可提出有理由的
Praxys 护栏，但不能冒充 published 值。

## Design：体验决定与规格草案

Owner: Design。沿用赛道核对及 Field Lab 视觉系统；本轮没有 UI 实现或渲染证据。

- 入口明确日常／比赛；比赛区分首次完赛和表现。无赛事不虚构日期，50 公里支持服从科学规则。
- 三预设只是填表，健身房非必填；独立确认资源、器械、熟悉度、经历和日期。
  确定、待定、不可用、未知分别显示，不从月频描述生成日期。
- 生成前显示可支持模块与缺口；生成后显示实际包含／未安排及原因；采用后显示已安排。
  模块用途不是能力获得，不显示虚假“赛事准备完成”状态。
- 保留设置、支持、生成、审阅修改、明确采用、反馈、复核流程；比赛显示阶段与后续重点，
  日常显示滚动训练。每节课说明实际类型、目的、步骤、器械及已接受的剂量和休息。
- 中文统一“跑步机”，坡度百分比与器械档位分开，不默认至少 10% 或未经依据换算。
  同日跑步和力量两张卡、独立完成；撤销一日一课推导的四天界面限制。
- 资源变化使旧提案需要重验；采用后标出受影响课，明确采用后继才替换未来未完成内容。
  已完成保留；容量不足逐项解释，不自动补课。
- 覆盖历史／器械缺失、容量或模块受限、未开放、未知版本、保存失败等状态；离线编辑只在
  内存标未保存，重连比较服务器版本并处理冲突，不假报保存或采用成功。
- 沿用暖纸、绿色行动、钴蓝解释、数字字体及 ScienceNote，不新增视觉原语。未来 P7 经
  UI Quality／Impeccable 验证 EN/zh、桌面／移动、明暗、长内容、键盘、读屏、触控和离线冲突。
- Web 首发；小程序兼容阅读并明确引导 Web 编辑，不能丢失双课；gate-off 保留读取及数据权利。

## Architecture：契约与原子交付草案

Owner: Architecture。仅界定后续实现依赖；没有为生产分配新 schema 或迁移版本。

- 目标显式区分比赛与日常，日常使用滚动窗口、训练目标和有期限资源，不造赛事或无限延长条件。
- 每课有稳定独立身份，日期只是安排；实际类型、多个用途标签、顺序与独立完成分开。
  新力量／跑步机结构必须保留 WorkoutV1 解释与旧计划读取。
- 时间合计；跑量、垂直暴露、力量和恢复分别管理，不做无依据的分钟或下降米数折算。
- 提案绑定目标、条件、历史、科学和课程版本，采用重检；资源变化使草稿失效，已采用通过后继调整。
- P2 必须连同身份、新结构读写、采用、完成、修改、快照、修订、导出和必要客户端兼容交付；
  P3 连同来源、确认版本、授权、撤回、导出、删除交付。不能把这些完整性义务推迟到 P8。
- P4/P5 是纯规划，不接运行入口；P6 统一 14/7 编排和采用事务；P7 完成 Web，P8 负责发布准备。

## Trust：数据、权限与开放草案

Owner: Trust。用户授权创建跟踪材料及 draft PR，不表示新科学接受、个人数据采集或激活。

- 所有对象由认证会话确定所有者，每位用户只访问自己的数据；客户端不能声明来源、观察事实或版本权威。
  严格有界输入，少记录、陈述、确认没有和真实零分开，不将陈述升级为观测。
- 不强制健身房字段。50 公里包含 50,000 米，不能继续套用旧 49,999 米上限声称已支持。
  日常模式资源有效期、重确认、全周期批量上限与快照保留规则须在相应契约评审冻结。
- 同日课有独立 ID、顺序和版本；保留完成课，未来课只通过明确采用更改。
- 权利覆盖每课、当前条件、目标、提案、PlanRevision、审计及缓存；未知 schema 不执行，
  仍可原样读取、导出与删除。reset 不等于删除。关闭 gate 不移除数据权利。
- 复用服务端 Statsig，只使用现有身份，不新增训练、赛事、资源或健康属性及值遥测。
  当前不变更 SDK、配置、数据收集或任何生产状态。
- provider 零访问、零投递；采用和后续调度不能访问凭据、连接、适配器、发送、替换、重试或对账路径。

独立 Quality 须在后续精确实现检查各用户角色、未知版本、版本冲突、重复采用、权利级联和
provider 零调用；Engineering 的开发检查不代替该验证。部署及运行配置在 P8 另行路由 Operations。
