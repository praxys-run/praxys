# Designated DFA V2 tooling proposal

This mechanism is a tooling bridge, with no canonical V2 record, runtime migration,
Science approval or activation. V1 remains terminally stopped. The bridge itself
must first pass the existing trusted V1 stopped-maintenance admission path,
independent Trust/Quality review, current checks and concrete maintainer review.
A candidate cannot certify its own new protocol.

`analysis/science_admission_amendment.py` parses the existing named parameter
`admission_amendment.value` into a dedicated strict type. It changes no historical
record defaults or serialization. Only `sdr-activity-dfa-alpha1-v2`, integer 2,
artifact approval, empty supersedes and explicit null superseded_by are supported.
The value requires exact baseline decision, contract, implementation envelope,
shared evidence, terminal STOP, five numerical group values, method, manual
statement revision and modality pins. Registry consistency is local; privileged
admission separately checks the authenticated exact Git base and all historical
science bytes and executable modes. The only historical index allowance requires
an exact current rendering of REGISTRY.md. Neither candidate data nor a boolean
can supply authenticated admission.

The separate V2 composite marker is `praxys-science-activation:v2`, with schema 2,
purpose `dfa-v2-activation` and the pinned baseline STOP. It contains exactly two
new assertions: V2 decision and V2 implementation. Shared Evidence approval/date
are retained without renewal. Legacy V1 comments, binding serialization and
validation payloads keep their formats. Decision-only acceptance requires the
existing authenticated stopped-maintenance context with actual V1 denial;
activation additionally requires exact V2 validation and replay.

The V2 controller runs three fresh bounded observation children: draft,
accepted-inactive and projected-active. All keep the actual V1 STOP and shared
accepted Evidence intact. Hypothetical V1 fixtures instead prune the entire
semantic V2 closure before changing disposable V1 lifecycle state. They cannot
prove historical V1 denial.

The future callable interface is explicit: manual `api.activity_dfa.require_policy`,
automatic `api.dfa_automatic.require_policy`, and retained historical
`api.activity_dfa.require_historical_v1_policy`. Manual method identity/fingerprint
come from `analysis.activity_dfa`; automatic identity comes from
`analysis.dfa_source.AUTO_SDR_ID` and its full method/parameter fingerprint is
exposed by `api.dfa_automatic`. Each callable must be defined in its named module.
The observer binds module paths and every loaded application dependency to the
candidate, along with returned contract/method/full parameter values. Both future
branches must deny before activation, both must return exact V2 in projected
active state, and the historical callable must always deny V1. These future
callables are absent in the shipped implementation: an actual V2 probe fails.
Disposable simulated callables test only this protocol and supply no runtime proof.

Children use an absolute interpreter/script with `-E -B -P`, a credential-free
minimal environment, one strict typed JSON result, 60 seconds and 16 KiB aggregate
stdout/stderr. Nonzero exit, malformed/partial/duplicate output, nested scalar
coercion, timeout, overflow or failed cleanup cannot complete validation.
Typed stdout remains untrusted and does not replace independent source review.

Regression, observation and the trusted collector run on separate fresh runners.
The collector and authenticated readers never import candidate code. V2 proof
binds purpose/subject, amendment and actual baseline denial, repository/PR,
base/reviewed head/full tree delta, trusted workflow/revision, successful required
jobs, run and attempt. Artifact ID, name, archive digest and run association are
bound through authenticated metadata and the implementation envelope; the payload
digest contains no self-reference. Post-approval source must match exact replay.

Later corrected V2 Science materialization, runtime migration, rights/source/gate
boundaries, approvals, physical drain evidence and release are separate work.
Numerical value inheritance does not establish numerical equivalence. Runtime
cessation and complete actor retirement remain separate operational observations.
