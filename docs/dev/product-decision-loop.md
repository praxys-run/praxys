# Product decisions within a task

The main session owns the user problem, scope, alternatives and implementation.
Read `PRODUCT.md` and relevant evidence. Resolve routine reversible choices from
the user's request and accepted product behavior. Ask only about a material
ambiguity or choice that affects the result; prepare a concrete recommendation.

Record the choice and rationale in the task or PR. Reuse an existing Product
Decision Record when relevant; create a durable record only when it helps a
future reviewer understand a long-lived decision. Product reasoning does not
require a Product agent or a nested workflow.

Scientific support, safety limits, UI quality and release authority remain
separate constraints. Read the relevant skills and contracts, and obtain the
independent review required by [the execution policy](agentic-operating-model.md).
The same session may draft both product reasoning and scientific artifacts,
while scientific acceptance and activation retain their distinct approval roles.
